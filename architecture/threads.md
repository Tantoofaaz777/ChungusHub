# Threads

Threads simulates a fictional audience discussing manually selected roleplay messages. It is a separate engine and per-chat feed, never part of the story send pipeline, Chat Memory, or prompt replacement. Its top-bar button opens Feed / Make; global enable, instructions and continuity windows live in Settings → Engines → Threads. Connections routes `threads` exactly like other calling engines and supplies all sampling settings.

Make lists only unused messages on the current active path. Individual toggles support sparse selection, Shift-click and touch hold add a range. Hidden messages remain selectable. Generation sorts selections chronologically and snapshots original text, role, speaker and position. The prompt contains recent selected text, optional earlier selected scenes, active earlier feed versions, per-chat Fandom Notes and optional AO3 metadata. Story messages are sent as content only, separated by two newline characters, without speaker names, roles, numbers or scene labels. The Previous / Recent Context section headings remain. It never fills selection gaps with unselected RP messages. Earlier scenes and audience feeds have independent modes: round/thread counts or model-aware token budgets. Existing settings retain count mode and both numeric limits survive switching modes. Story token budgets keep the newest suffix of whole original messages, counting only the original message content and blank-line separators; fandom budgets keep a suffix of whole active feeds. A zero limit omits that channel. The current selected scene, notes, instructions and AO3 metadata are outside these historical budgets and are never silently truncated. Context is checked against the assigned connection's prompt budget before making a model call.

Generation is an independent `llmService.complete` call labeled `threads`. Invalid JSON or invalid discussion nesting is reported without consuming source messages. Valid results are saved immediately; a failed save retains the generated result for retry without another model call. Cancel aborts the call; opening Threads in another chat cancels a pending generation. Closing the panel preserves it. Feed versions use the original source snapshots; right swipe at the final version generates another, and active version controls future audience context. Feed text is rendered as text, not model-provided HTML.

SQLite migration 49 adds `threads_rounds` and `threads_notes`, both cascading with chat deletion. A new round validates all source IDs, order, role and original contents on one branch, allowing gaps and hidden messages, and rejects overlapping scenes that could coexist on a branch atomically. A captured `branchLeafId` pins validation to the branch read when generation began, even if another device changes the active leaf. Older clients fall back to the current chat path. Same-ID save retries are idempotent. Versions and deletions check revisions; a generation cannot recreate a deleted round. New RPC methods use the `threads` sync scope. Notes and AO3 use independent field patches and serialize writes; failures keep local edits available for retry. Generated feeds and source snapshots survive edits to the original messages.

The feed follows Threadverse's Reddit-style presentation: stable colored initial avatars, author rows, post titles, vote capsules, comment counts, independent root conversation separators and reply guide lines. Engagement scores and Reply / Share glyphs are display-only; functional copy, regenerate, delete and version navigation remain in the thread toolbar. These visual indicators are not focusable buttons. All surfaces use Chungus theme colors, and reply indentation is capped for narrow screens.

## Forks and copies

A message fork stays in the same chat. Common-prefix rounds are inherited by path membership: only rounds whose entire sparse source belongs to the active branch feed continuity and consume selectable messages. Partial and other-branch scenes stay in Feed as an archive marked "Outside this branch"; they can be copied, deleted and browsed, but require their original branch to regenerate. Shared-prefix turns may be used in a new divergent scene only if that scene contains a fork-specific turn, so switching back cannot activate two overlapping scenes on one path. Both preflight and the server enforce that rule.

`duplicateChat` copies the full message forest and inherits all complete Threads rounds in the same transaction, independently of the Chat Memory option. The shared inheritance helper supports partial prefix maps, skips scenes with unmapped/deleted sources, remaps message, round and version IDs, keeps source snapshots and timestamps, resets revisions and preserves the active version. Notes and AO3 metadata are copied too. Source and child can then change independently; duplicating a copy remaps again. Internal same-chat forks share their common-prefix records rather than duplicating them. There is no lazy recovery/import step that can resurrect a deleted inherited thread.

Instruction preset libraries, outgoing regex selection and automatic version pruning are not implemented yet. All original feeds remain stored with their original chat, including snapshots whose source messages are later removed. Such orphaned scenes do not enter branch continuity or consume surviving messages, and are not inherited by copies.
