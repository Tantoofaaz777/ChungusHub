# Threads

Threads simulates a fictional audience discussing manually selected roleplay messages. It is a separate engine and per-chat feed, never part of the story send pipeline, Chat Memory, or prompt replacement. Its top-bar button opens Feed / Make; global enable, instructions and continuity windows live in Settings → Engines → Threads. Connections routes `threads` exactly like other calling engines and supplies all sampling settings.

Make lists only unused messages on the current active path. Individual toggles support sparse selection, Shift-click and touch hold add a range. Hidden messages remain selectable. Generation sorts selections chronologically and snapshots original text, role, speaker and position. The prompt contains recent selected text, optional earlier selected scenes, active earlier feed versions, per-chat Fandom Notes and optional AO3 metadata. Story messages are sent as content only, separated by two newline characters, without per-message speaker names, roles or numbers. Previous / Recent Context use `## Episode / chapter` headings as in Threadverse; consecutive earlier scenes with the same title share a heading. Untitled saved rounds use `ROUND n`, and an untitled current scene uses `CURRENT RANGE`. It never fills selection gaps with unselected RP messages. Make always shows the context card with Reset continuity, previous context and a compact recent-context meter. Only the optional Episode / chapter field requires a nonempty selection. Message previews show up to three lines. The recent-context meter uses (`1 msg • 257 tok • FP ~1,030 tok`). Previous context lists the titles of the scenes actually retained by the story-context window, oldest first and separated by `•`, or None yet if none are retained. It uses the same assembly result as FP, including partial scenes retained by token budgets. Source tokens use the assigned model’s tokenizer after macro expansion; FP estimates the complete prompt with the same assembly path as generation, including historical budgets, instructions, notes, enabled AO3 metadata and JSON instructions, with the learned model calibration. Full-prompt counting is debounced and ignores superseded results; it never calls the model. The fandom-continuity readout is omitted from this card, while continuity still participates in generation and FP. Earlier scenes and audience feeds have independent modes: round/thread counts or model-aware token budgets. Existing settings retain count mode and both numeric limits survive switching modes. Story token budgets keep the newest suffix of whole original messages, counting the episode headings, original message content and blank-line separators; fandom budgets keep a suffix of whole active feeds. A zero limit omits that channel. The current selected scene, notes, instructions and AO3 metadata are outside these historical budgets and are never silently truncated. Context is checked against the assigned connection's prompt budget before making a model call.

During generation, Threads reuses the chat’s three-dot indicator and shows separate reasoning and response token estimates from received text, counted with the assigned model’s tokenizer at most ten times a second. Estimates carry `~`; unavailable streams show a dash. Cancelled or superseded calls cannot update progress. Provider aggregate completion usage is not presented as an exact split. Generation is an independent `llmService.complete` call labeled `threads`. Invalid JSON or invalid discussion nesting is reported without consuming source messages. Valid results are saved immediately; a failed save retains the generated result for retry without another model call. Cancel aborts the call; opening Threads in another chat cancels a pending generation. Closing the panel preserves it. Feed versions use the original source snapshots; right swipe at the final version generates another, and active version controls future audience context. Feed text is rendered as text, not model-provided HTML.

Make also offers the native prompt dropdown for the current chat. An unset or deleted preset follows the engine default; an explicit selection uses that preset without changing the global selection. This per-chat reference is synced with the Threads notes, copied with duplicate chats and shared by same-chat forks. Generation snapshots the resolved instructions. SQLite migration 50 adds the nullable prompt reference to threads_notes. SQLite migration 49 adds `threads_rounds` and `threads_notes`, both cascading with chat deletion. A new round validates all source IDs, order, role and original contents on one branch, allowing gaps and hidden messages, and rejects overlapping scenes that could coexist on a branch atomically. A captured `branchLeafId` pins validation to the branch read when generation began, even if another device changes the active leaf. Older clients fall back to the current chat path. Same-ID save retries are idempotent. Versions and deletions check revisions; a generation cannot recreate a deleted round. New RPC methods use the `threads` sync scope. Notes and AO3 use independent field patches and serialize writes; failures keep local edits available for retry. Generated feeds and source snapshots survive edits to the original messages.

Feed shows one saved scene at a time. A native browser select below Feed / Make lists chapter names only, newest first, with previous/next chapter arrows separate from version swipes. It starts on the newest scene, opens locally saved results, preserves the viewed scene across version updates and new scenes synced from other devices, and falls back to the newest if it is deleted. The viewed round ID lives beside Feed / Make in the store; chat changes reset it. Browsing does not change continuity or the active story branch. The browser handles opening, dismissal and keyboard navigation for the chapter select. The feed follows Threadverse's Reddit-style presentation: stable colored initial avatars, author rows, post titles, vote capsules, comment counts, independent root conversation separators and reply guide lines. Engagement scores and Reply / Share glyphs are display-only; functional copy, regenerate, delete and version navigation remain in the thread toolbar. These visual indicators are not focusable buttons. All surfaces use Chungus theme colors, and reply indentation is capped for narrow screens.

## Forks and copies

A message fork stays in the same chat. Common-prefix rounds are inherited by path membership: only rounds whose entire sparse source belongs to the active branch feed continuity and consume selectable messages. Partial and other-branch scenes stay in Feed as an archive marked "Outside this branch"; they can be copied, deleted and browsed, but require their original branch to regenerate. Shared-prefix turns may be used in a new divergent scene only if that scene contains a fork-specific turn, so switching back cannot activate two overlapping scenes on one path. Both preflight and the server enforce that rule.

`duplicateChat` copies the full message forest and inherits all complete Threads rounds in the same transaction, independently of the Chat Memory option. The shared inheritance helper supports partial prefix maps, skips scenes with unmapped/deleted sources, remaps message, round and version IDs, keeps source snapshots and timestamps, resets revisions and preserves the active version. Notes and AO3 metadata are copied too. Source and child can then change independently; duplicating a copy remaps again. Internal same-chat forks share their common-prefix records rather than duplicating them. There is no lazy recovery/import step that can resurrect a deleted inherited thread.

Fandom instructions have named presets in Settings → Engines → Threads. The native dropdown and new/rename/delete controls sit below the field label. New copies the current text; edits auto-save into the selected preset, pending edits flush before switching, and the expanded editor edits that same draft. Reset changes only the selected preset to the shipped instructions. At least one preset remains. The library and active selection live atomically in the synced featurePrompts setting; existing instructions seed the first preset. Delayed edits retain their original preset ID and cannot recreate deleted entries. Settings writes are serialized and pending writes guard reloads. The effective active text is mirrored into the legacy override. Preset changes affect future generations, not saved discussions. Outgoing regex selection and automatic version pruning are not implemented yet. All original feeds remain stored with their original chat, including snapshots whose source messages are later removed. Such orphaned scenes do not enter branch continuity or consume surviving messages, and are not inherited by copies.

ChungusHub is AGPL-3.0-or-later; the root LICENSE supplies the license text. Spindle-specific backend, storage and UI have been replaced by native Chungus services and Svelte components.

Reset continuity in Make always asks for confirmation, then atomically deletes all rounds and versions in that chat, including archived branches. The confirmed round IDs and revisions must still match; concurrent changes reject the reset. Source messages (including hidden flags), notes, AO3 data and the selected prompt remain intact. Removing rounds makes their sources selectable again.

The Threads panel is lazy-retained for the current chat. Closing preserves Feed/Make, selected episode, source selection, expanded AO3/notes and scroll. Reopening calls ensureLoaded, which reuses loaded data or an in-flight read; explicit load/retry/live sync still fetches current data. Hidden prompt previews stop counting and retain one result keyed by prompt input, model and calibration. Notes flush and touch-selection timers stop on hide. A chat switch replaces local view state; visible loading is gated by the store chat ID to avoid displaying a previous chat’s feed.

`loaded` means data has arrived for the current chat at least once. Reconnects, live sync and explicit refreshes keep it true while reading in the background (`refreshing`), so neither Feed nor Make is replaced by a loading placeholder. Read failures use a separate `loadError` with retry, retaining the last data and any generation/save error. Only the latest read may publish data, errors or completion state; a chat change clears loaded data and the viewed round before fetching the new chat. Snapshot reconciliation preserves saves, deletions and continuity resets completed during the read, while accepting higher server revisions. Notes, AO3 and prompt selection retain field edits and writes pending at the start of the read, even if saving finishes before the older response arrives.

Make mounts the first 50 unused message previews, then appends up to 50 more when its own scroller reaches within 200px of the end. A Load more messages button provides a keyboard/manual fallback. The loaded prefix survives Feed/Make and panel toggles for the current chat; switching chats creates a fresh prefix. This is progressive rendering, not a source-data limit or full virtualization: previously loaded rows remain mounted as the reader scrolls. Selection, Shift/touch intervals, token previews and generation always use the complete source list, including selected rows outside the rendered prefix. Hidden panels and generation do not auto-expand the list.
