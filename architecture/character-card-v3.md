# Character Card V3

Implementation follows [SPEC_V3.md](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md). `concepts.md` is an earlier proposal and is not the implementation target.

The import picker accepts PNG/APNG (`ccv3` preferred over `chara`), JSON and CHARX (`card.json` at the ZIP root, STORE or DEFLATE). The export dialog defaults to V3 and offers PNG, JSON and CHARX; V2 PNG/JSON remains available. PNG/APNG chunks are handled without decoding the image for card extraction. Export retains animation chunks when the stored portrait remains APNG.

`CharacterCardMetadata` lives in the existing library data JSON, so variants and database backups carry it without a schema migration. Standard character fields stay in the existing trait editor. Nickname uses the in-story alias. The V3 panel exposes translated creator notes, original sources, timestamps, group greetings and assets. Notes select browser language, then English, then the original notes. Sources are read-only.

Portraits and backgrounds are integrated with the existing image controls. Emotion and extra-image assets remain portable metadata; this fork has no gallery, sprite display, or sprite engine. A main background seeds the scene of new chats. User icons can create personas; selecting that persona supplies its asset name to `@@is_user_icon`. Portable originals remain in metadata for lossless asset export even when the image store optimizes its local copy. CHARX rewrites data URI assets to `embeded://assets/...` (the spelling is specified by V3). JSON and PNG retain data URIs. PNG asset text chunks using `__asset:` are also read. External HTTPS assets use the authenticated `/api/card-assets/fetch` endpoint with public address validation, pinned DNS, bounded redirects, timeouts and a 25 MiB response limit; total imported asset bytes are bounded. Failed assets produce a visible warning and keep their reference.

Group chats, audio playback, 3D viewers and executable asset engines are not part of ChungusHub. Their greetings/asset bytes and unknown fields are preserved for compatible apps. Downloaded code or HTML is never executed. Instruct-only decorators are ignored in the chat pipeline, allowing supported fallback decorators to apply. `@@reverse_depth` is also ignored in chat as the specification requests. UI-prompt disabling is optional in the spec and is ignored because the app has a custom preset pipeline instead of those named UI prompts.

V3 books preserve original optional entry fields and explicit `use_regex`/`selective` semantics. Literal slash keys stay literal; regex mode ignores constant/secondary keys and invalid patterns do not match. Runtime decorators are interpreted on a copy, stripped before sending, and leave authored content intact. They support activation conditions, branch history, scan depth, chat role/depth, field positions, additional/excluded keys and priority/token budgets. A position absent from the enabled preset is ignored, so a fallback or ordinary lorebook placement can apply. `@@ignore_on_max_context` yields before examples/history when the assembled prompt is too large, using the same scan and probability rolls. Standalone V3 books export as `lorebook_v3`; native World Info exports preserve the V3 matching metadata too.

CBS handling is shared between messages, prompt expansion and lore scans. `char`/`user` are case insensitive; random/pick support escaped commas; dice accept `N` or `dN`; reverse handles Unicode code points. Comments never reach prompts or scans; inline comments remain visible in messages. Hidden keys are only exposed to recursive scans. Pick is stable for the same input seed.

Regression tests cover both containers and prompt behavior: `characterCard.test.ts`, `lorebook/card-v3.test.ts` and `server/card-assets.test.ts`. Existing V1/V2 and native-version tests remain applicable. Per-card metadata is preserved independently of whether the user chooses to add its embedded book to the shelf; explicitly unlinking all books prevents re-exporting an old book by accident.
